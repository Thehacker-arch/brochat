# BroChat Android APK (Tauri)

The mobile app is a **Tauri 2** shell around the same Vue UI. The WebView’s origin is **`https://tauri.localhost`**, not your server — API URLs must be set at **build time** (see `UI/frontend/src/config.ts` and `.env.production.example`).

## Prerequisites (build machine: macOS / Linux / Windows)

- **Rust** + `cargo`
- **Node.js** + npm
- **Tauri CLI**: `cargo install tauri-cli --version '^2.0'`
- **JDK 17** (required for Gradle — without this you get *Unable to locate a Java Runtime*)
- **Android Studio**: SDK, **NDK**, build-tools

### Environment variables (run in the **same terminal** before `cargo tauri android build`)

macOS (Android Studio’s bundled runtime — preferred):

```bash
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
export ANDROID_HOME="$HOME/Library/Android/sdk"
export NDK_HOME="$ANDROID_HOME/ndk/$(ls -1 "$ANDROID_HOME/ndk" | head -1)"
```

Verify Java is visible:

```bash
"$JAVA_HOME/bin/java" -version
```

If `JAVA_HOME` points to a missing folder, install [Android Studio](https://developer.android.com/studio) or install JDK 17 (e.g. `brew install openjdk@17`), then:

```bash
export JAVA_HOME="$(/usr/libexec/java_home -v 17)"
```

Install Rust Android targets (ARM devices):

```bash
rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
```

## 1. Point the app at your live server

From the **repository root** (`brochat/`), paths are `UI/frontend/`. If `cd UI/frontend` fails, you are not in the repo root.

```bash
cd UI/frontend
cp .env.production.example .env.production
# Edit VITE_API_BASE_URL / VITE_WS_BASE_URL if your domain differs
```

Production build bakes these into the JS bundle.

## 2. Build the web assets

```bash
cd UI/frontend
npm ci
npm run build
```

## 3. Debug APK (local testing only)

From `UI/frontend`, with `JAVA_HOME`, `ANDROID_HOME`, and `NDK_HOME` set:

```bash
cd UI/frontend
cargo tauri android build --debug -- --apk
```

Output is under `src-tauri/gen/android/app/build/outputs/apk/` (e.g. `.../debug/...`). Fine for sideloading; **not** what you upload to Play.

## 4. Signed release build (Play Store–ready)

Google Play expects a **signed Android App Bundle (AAB)** for new apps. You can also build a **signed release APK** for sideloading or testers.

### 4.1 Create an upload keystore (once)

Keep this file and passwords safe — you need the same key for every update on Play.

```bash
keytool -genkey -v -keystore ~/brochat-upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias brochat
```

### 4.2 Configure Gradle signing

1. Copy the template into the Gradle project (use the **stable** path under `src-tauri/` — the `gen/android` folder may be regenerated by Tauri):

From the **repository root**:

```bash
cp UI/frontend/src-tauri/keystore.properties.example \
   UI/frontend/src-tauri/gen/android/keystore.properties
```

From **`UI/frontend`**:

```bash
cp src-tauri/keystore.properties.example src-tauri/gen/android/keystore.properties
```

2. Set `password`, `keyAlias`, and **absolute** `storeFile` path to your `.jks`.

The project’s `app/build.gradle.kts` already wires **release** builds to `keystore.properties` when that file exists.

### 4.3 Version for Play Store

`versionCode` must increase for every Play upload. Tauri derives it from `src-tauri/tauri.conf.json` → `version` (see [Tauri Google Play](https://v2.tauri.app/distribute/google-play/)). You can override with `bundle.android.versionCode` if needed.

### 4.4 Build **signed AAB** (upload this to Play Console)

```bash
cd UI/frontend
npm run build
cargo tauri android build --aab
```

Default is **release** (omit `--debug`). With `keystore.properties` present, the bundle is **signed**.

Typical output path:

`UI/frontend/src-tauri/gen/android/app/build/outputs/bundle/universalRelease/app-universal-release.aab`

In Play Console: **Release** → create a release → upload that `.aab`.

### 4.5 Build **signed release APK** (optional — e.g. WhatsApp / direct install)

```bash
cd UI/frontend
npm run build
cargo tauri android build --apk
```

Look under:

`UI/frontend/src-tauri/gen/android/app/build/outputs/apk/`  
(e.g. `universalRelease/` or per-ABI folders if you use `--split-per-abi`).

### 4.6 Play Store checklist (outside the build)

- [Play Console](https://play.google.com/console/) developer account and app listing  
- Privacy policy URL, content rating, screenshots, etc. ([release checklist](https://play.google.com/console/about/guides/releasewithconfidence/))  
- App signing: first upload is manual; Google may offer **Play App Signing** — follow their wizard  
- Icons: run `cargo tauri icon /path/to/icon.png` from `UI/frontend` (see [Tauri Google Play](https://v2.tauri.app/distribute/google-play/))

**Note:** If Tauri regenerates `gen/android/`, re-copy `keystore.properties` and confirm `app/build.gradle.kts` still contains the `signingConfigs` block (this repo ships it patched in).

## 5. Server checklist

- Backend **CORS** must allow the Tauri origin. Defaults in `backend/src/main.rs` include `https://tauri.localhost`. In production, set:

`ALLOWED_ORIGINS=https://brochat.duckdns.org,https://tauri.localhost`

- API must be **HTTPS** and WebSockets **WSS** (release Android build uses cleartext off).

## Icons

Add app icons under `UI/frontend/src-tauri/icons/` and list them in `tauri.conf.json` → `bundle.icon` so the APK shows a proper launcher icon.

## Troubleshooting

### `Unable to locate a Java Runtime` / Gradle exits after Rust builds

Gradle needs a JDK. Export `JAVA_HOME` to Android Studio’s JBR or to JDK 17, then open a **new** terminal (or `source` your profile) and run `cargo tauri android build` again from `UI/frontend`.

### `cd: no such file or directory: UI/frontend`

You are not in the `brochat` repository root. Use `cd /path/to/brochat/UI/frontend` or `cd ~/Desktop/brochat/UI/frontend` (adjust to your clone path).
